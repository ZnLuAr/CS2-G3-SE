# 设计决策记录

> 用于记录"为什么这么做"——技术选型、架构分层、模块划分、范围取舍等。
> 技术报告要求论证设计决策与权衡，写报告时直接用这里的内容。

---

## 模板（复制以下结构添加新条目）

### [YYYY-MM-DD] 决策标题

- **背景**：当时遇到的问题或需要做的选择
- **选项**：考虑过哪些方案（至少列出两个）
- **决定**：最终选择
- **理由**：为什么这么选，依据是什么（用户需求、团队技能、课程要求、可维护性……）
- **影响**：这个决策影响了哪些模块 / 文档

## 决策记录

### [2026-09-08] 仓库初始化：先建仓库与协作规范，后定骨架

- **背景**：项目主题与规模尚未确定，无法立即搭建代码骨架，但需要尽快有可协作的 GitHub 仓库
- **选项**：
  - 等选题确定后一次性搭好骨架再建仓库
  - **先建仓库**（README、`.gitignore`、`.gitattributes`、协作规范），骨架后补
- **决定**：先建仓库
- **理由**：
  - 课程时间线紧（9-14 分组截止、9-25 提案截止），仓库尽早可用，组员可以先熟悉协作流程
  - Git 教学（新手友好的工作流 FAQ）放进 README，等代码骨架就位时组员已经过了 Git 上手期
  - 骨架依赖选题与规模，贸然搭建返工成本高
- **影响**：仓库结构（README、docs/）；后续骨架搭建时会补 `src/`、`tests/` 等
