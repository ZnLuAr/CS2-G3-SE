# dev-materials-for-report/

本目录用于存放**面向最终报告与阶段进展汇报**的开发素材：决策记录、开发日志、测试笔记、会议记录等。

> 这些文件的内容会在技术报告和各次进展汇报中被大量引用——边开发边写，比临近截止时间才回忆要轻松得多。

## 文件总览

| 文件 | 用途 | 对应交付物 |
|------|------|--------------|
| [`design-decisions.md`](./design-decisions.md) | 设计决策记录："为什么这么做" | 技术报告 / 答辩 |
| [`development-log.md`](./development-log.md) | 时间线式开发日志：什么时候改了什么 | Project updates / 技术报告 |
| [`testing-notes.md`](./testing-notes.md) | 测试与调试笔记：发现的 bug 与修复过程 | 技术报告 / PoC |
| [`meeting-notes.md`](./meeting-notes.md) | 会议记录：组会、与导师的 meeting | Project updates / 答辩 |

> 当前的功能清单、系统设计和参与指引在 [`docs/` 根目录](../README.md)，本目录只记录实际发生的过程。

## 与外层 docs/ 的分工

- **`docs/` 根目录**：面向"项目本身"的稳定文档（需求、架构设计、课程资料）
- **本子目录**：面向"开发过程 / 报告素材"的文档（迭代记录、决策推演、bug 排查、会议纪要）

## 写作建议

- **当场记**：决策、踩坑、反思应该开发过程中**当场**写进对应文档，不要拖到最后回忆
- **统一格式**：每条记录建议带日期 `[YYYY-MM-DD]`，便于追溯
- **直接面向报告**：写文档时就当作是在写报告，最终可以直接复用内容
- **会议记录别偷懒**：与导师的会面尤其重要——导师给的建议、认可/质疑的方向，写进报告就是我们沟通并改进项目的证据
