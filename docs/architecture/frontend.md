# 前端架构与交互合同

本分册描述浏览器端应用的页面、路由、状态、交互和 API 使用方式。系统总览见[总架构](../architecture.md)，后端字段、权限、错误响应、事务和请求结果核实以[后端架构](backend.md)为完整合同。前端全部由 Lvzhen ZHOU 负责，业务功能、后端关联和依赖以 [`feature-list.csv`](../feature-list.csv) 为准。

## 1. 范围与当前状态

Web 前端是独立于默认 CLI 的交互入口，通过 Web API 调用 Logic 用例。CLI、可选 TUI 和 Web API 共用后端业务规则；浏览器应用负责输入采集、页面状态、响应展示和交互反馈。

浏览器代码位于 `frontend/`，后端 HTTP 适配层位于 `src/web/`。前端提供 Vue 应用装配、角色路由、登录表单、身份恢复、公共 API 客户端和业务页入口；后端提供登录、身份与退出路由，认证 Logic 仍为占位。业务表单、领域 API 适配和待核实命令存储仍待实现；通知列表按查询缓存刷新。候补历史重入与空位分配规则见后端合同中的待确认项。

## 2. 技术分层

前端采用 TypeScript、Vue 3 和 Vite。Vue Router 负责页面导航，Pinia 管理身份和当前操作者，TanStack Query 管理列表、详情和其他服务端状态，Axios 作为 HTTP 客户端。组件输入与输出遵循前后端合同。

目录按功能域组织，公共能力单独放置：

数据流保持单向：页面或组件提交输入，功能域 API 层调用公共客户端，查询层管理服务端状态，组件根据状态渲染结果。共享身份状态提供角色入口和可用动作；业务权限、余额计算、预约冲突和事务规则由后端 Service 和 Logic 执行。

## 3. 身份、路由与角色入口

登录成功后，当前操作者保存在内存，访问凭据和过期时间保存在当前标签页的 `sessionStorage`；刷新时读取凭据并调用 `/api/auth/me` 恢复身份。退出、过期或切换账号时终止旧请求、清理凭据和私有查询缓存，再进入对应页面。会话代次随清理更新，旧身份复核、请求和退出操作的迟到结果只属于原会话。凭据格式、声明和过期处理以[后端 API 合同](backend.md)为准；浏览器把访问令牌作为不透明字符串交给 API。

路由使用 `meta.roles` 声明可进入的角色。角色标识为 `member`（会员）、`coach`（教练）、`receptionist`（前台）和 `admin`（管理员）。公共登录页另设 `meta.public=true`；其余页面先恢复并校验身份，再检查角色。已登录用户访问登录页时转到本角色入口，越出角色范围时显示无权访问提示。

## 4. API 调用约定

前端 API 模块按功能域提供查询和命令函数。公共客户端负责身份头、超时、响应解码和统一错误响应对象；功能域按命令合同提供请求编号。后端完整路由、字段、状态码和错误映射见[后端 Web API 合同](backend.md#17-web-api)。

后端详情直接映射为 View，列表映射为 `Page[T]`。Python 字段使用 `snake_case`，HTTP JSON 统一使用 `camelCase`，由后端 API 的序列化别名转换；前端类型与 HTTP 字段保持一致。同一功能的查询和命令使用固定类型。

TypeScript 类型按后端合同建立：有限状态映射为联合字面量，`kind` 字段映射为判别联合，分页映射为 `Page<T>` 泛型，可空字段保留 `null`。组件按 `kind` 读取期限卡或次卡的对应字段，状态值、字段和分页结构随后端合同同步。

业务 ID 统一为规范正十进制字符串，范围为 `1`～`9223372036854775807`，例如 `"9007199254740993"`；路径、查询、请求体、Actor 和错误 `recordId` 使用相同规则。公共类型 `EntityId` 和 `isEntityId` 表达并校验该范围，组件和查询键保留字符串原值。计数、页码、页大小和推荐分数继续使用 `number`。金额使用固定两位小数字符串。

`OperationName` 是支持请求结果核实的固定操作名集合。以下命令首次提交时生成 UUID 格式的 `requestId`（Python 字段为 `request_id`），同一操作者对同一份输入重试时保留原编号。

| 操作 | 后端操作名 | 前端功能 ID |
|---|---|---|
| 会员建档 | `create_member` | `FE-MEM-01` |
| 销售健身房卡及接续销售 | `sell_gym_card` | `FE-CARD-02` |
| 销售私教课包 | `sell_lesson_package` | `FE-PKG-04` |
| 创建课次 | `create_session` | `FE-COURSE-02` |
| 取消课次 | `cancel_session` | `FE-COURSE-03` |
| 创建预约 | `book` | `FE-BOOK-01` |
| 取消预约 | `cancel_booking` | `FE-BOOK-02` |
| 入场登记 | `register_entry` | `FE-CARD-11` |
| 加入候补 | `join_waitlist` | `FE-WAI-01`，随候补待确认项验收 |

这些命令在首次发送前，按当前操作者在本标签页的 `sessionStorage` 保存操作名、`requestId` 和冻结的业务输入。记录以 `ownerAccountId`、操作名和请求编号区分，业务字段采用对应 Input 合同；密码仅保留在登录表单内存并在提交结束后清空。存储失败时先提示恢复浏览器存储，再提交命令。

请求超时、连接中断或返回 `OutcomeUnknownError`（提交结果未知）时，先按原编号查询结果。查到结果后展示后端返回的当前 View、刷新相关列表并移除待核实记录；查不到时继续显示“结果待核实”，保留查询入口。确认重试时复用原编号与冻结输入。原结果确认后，用户改动输入并再次提交时生成新编号。身份恢复遇到暂时性错误时保留凭据并提供重试；后端返回 `action=login` 时清除凭据与私有缓存。

刷新页面后，先通过 `/auth/me` 复核操作者，再恢复属于该账号的待核实记录。身份恢复遇到暂时性错误时保留凭据，服务状态页提供重新验证；身份被判定失效时清除凭据与私有缓存。其他服务错误保留安全提示，返回首页后可重新进入功能。退出或切换账号时清理当前页面、内存请求和查询缓存，待核实记录按原账号保留在独立命名空间；原账号重新登录后恢复查询入口。标签页关闭时记录随 `sessionStorage` 生命周期结束。例如售卡响应丢失后刷新页面，仍先核实原销售编号，再决定重试。

签到、到场更正、消课、缺席、结束课次、退出候补、已读和状态维护按各自的自然幂等合同查询目标记录，再决定是否重试。标签重复新增按 `ConflictError` 提示并刷新现有标签。其他创建操作失败时，先按业务查询核对已有记录，再按该操作合同决定后续处理。

公共错误处理器读取后端的 `action`：`continue` 显示当前操作提示，`login` 清理身份与私有查询缓存并回到登录页，`exit` 显示应用错误页，`verify` 按原请求或记录编号核实结果。请求结果核实的权限与返回类型沿用后端合同。

查询键包含当前账号、功能域、目标编号及规范化筛选和分页条件；功能域向公共客户端传入查询取消信号。成功的写操作使相关查询缓存失效并重新获取，例如取消预约同时刷新我的预约、课次余位、课包余额和候补状态。查询失败保留上一次可用数据并显示刷新入口；命令失败保留用户输入，避免用户重新填写整张表单。

## 5. 公共页面行为

所有列表页面统一处理加载、空结果、错误、分页、排序和筛选状态。分页参数、排序字段和筛选值遵循后端 `Page[T]` 查询合同；刷新或离开页面后恢复条件的规则由功能域明确记录。

所有写入表单在提交前做类型、长度、格式和范围校验，在服务端错误返回后显示字段级或表单级提示。金额使用后端约定的十进制格式，时间显示为门店时区；日期筛选使用后端定义的前含后不含区间。

破坏性操作使用确认步骤，确认文本包含目标记录和会受影响的权益或预约。重复操作显示后端返回的当前结果；未知提交结果保留“结果待核实”状态，并提供原编号查询入口。

通知列表使用查询缓存的定时刷新更新未读数，默认间隔为 30 秒。查询参数使用 `unreadOnly=true`，读取 `Page.total` 显示未读数；分页列表和全部已读成功后重新获取计数。刷新只在当前会员身份有效且应用会话存在时执行，退出或切换账号时停止轮询并清理私有缓存。通知记录永久保留。

## 7. 关键业务页面

会员端通过“我的资料”查看本人档案，通过“我的订单”及权益来源链接查询付款、权益与赠送详情。课次浏览显示课程时间、教练、余位和可用课包；有余位时进入预约，满员时由会员明确确认加入候补。我的预约展示本人记录，并在允许时间提供签到和取消动作；取消成功后刷新课次、课包和候补查询。候补页显示 `waiting`、`promoted`、`cancelled`、`closed` 状态，等待时显示位置，转正记录链接到正式预约；历史状态与再次入队规则按待确认项接入。通知页显示递补或关闭结果，关联入口进入本人候补或预约记录，课次时间及终态由预约合同展示。推荐卡片显示后端提供的聚合理由并下钻到可预约课次。

前台端将会员选择、产品选择、金额确认、结果详情组合成销售流程；售卡和售课包成功后同时展示订单、付款、卡或课包及赠卡结果。入场页面明确选择期限卡、次卡或当日预约来源，并显示重复请求核实结果。预约办理页提供授权代预约、取消和代签到。前台和管理员在推荐查询中选择目标会员，推荐理由与可约课次使用同一 `REC-01` / `FE-REC-01` 合同。

教练端从本人课表进入学员名单，再进入签到、更正、消课、缺席、授权体测和本人课次评价查询。候补人数使用 `GET /api/sessions/{id}/waitlist-summary` 返回的 `WaitlistSummaryView`。课次到达结束时间且开放预约全部结算后，本课教练和管理员从课次页调用 `POST /api/sessions/{id}/complete` 结束课次；该动作随 `FE-COURSE-10` 验收。管理员端同时提供产品、赠卡规则、排课、账号、器械、评价查询、报表和日志入口；评价列表按后端定义的查询范围与分页展示。

## 8. 测试与交付顺序

构建、单元与浏览器测试分别使用 `npm run build`、`npm test` 和 `npm run test:e2e`，命令在 `frontend/` 执行。当前生产构建通过，Vitest 53 项通过，Edge Playwright 5 项通过。单元测试检查身份、角色导航、大整数编号、错误映射、请求取消、迟到退出隔离和公共组件；浏览器测试检查登录页、刷新、会员资料与订单入口、越权、401 与退出。模拟认证用例以 `mock` 标注，真实 API 流程随领域实现增加（环境、步骤与实际结果见[前端说明](../../frontend/README.md)）。

前端测试按功能 ID 对齐后端测试，至少覆盖：

- 登录、身份失效和角色路由
- 列表分页、筛选、空结果和详情跳转
- 正常写入、字段校验、权限拒绝和重复操作
- 第 4 节固定命令的 `requestId` 重试、提交结果未知后的核实、刷新恢复和操作者隔离
- 自然幂等操作刷新、标签冲突和身份切换缓存清理
- 预约、销售、入场、签到、消课等关键流程的真实 API 联调

先完成公共入口、API 客户端和登录，再按会员预约、销售入场、到课记录、管理统计、通知推荐的依赖顺序推进。前端可以在后端响应合同固定后使用模拟数据开发；接入真实 API 后必须重新执行权限、错误和结果核实验收。

可选 TUI 按 `UI-01`、`FE-UI-01` 记录终端界面交付，默认 CLI 独立启动。冻结延期和退卡退款分别关联 `EXT-01` / `FE-EXT-01` 与 `EXT-03` / `FE-EXT-03`；这些功能保持 P2“待确认”，规则确定后再增加对应交互。

## 9. 构建与部署合同

浏览器应用部署于站点根路径，生产静态服务托管 `frontend/dist/`。Vue Router 使用 History 路由；静态服务将 `/profile`、`/orders/:orderId` 等页面地址回退到 `index.html`，`/api/` 请求反向代理至后端并保留该前缀。前端构建时默认采用同源 `/api`，开发代理由 Vite 配置提供。

跨域直连时，在构建环境配置包含 `/api` 的 `VITE_API_BASE_URL`，后端允许相应浏览器来源并接收 Bearer 身份头。CSV 下载接入时，响应以 `Content-Disposition` 提供安全文件名，跨域配置暴露该响应头供客户端读取。生产静态服务及反向代理示例见[前端说明](../../frontend/README.md#生产部署)，部署验证按该环境单独记录。
