# 文档审计 Skill

全面审计架构文档（docs/architecture.md）与实际代码的一致性。**不追求速度，追求全面和准确**。

## 审计目标

确保架构文档与代码双向一致：
- 文档中描述的类型、函数、参数在代码中存在
- 代码中的公共接口在文档中有说明
- 类型定义、参数顺序、返回值类型匹配
- 业务规则的描述与代码注释一致

## 审计策略

**使用 sub-agent 进行模块化审计**：
- 将架构文档按章节拆分
- 为每个模块启动独立的审计 agent
- 每个 agent 负责一个模块的双向比对
- 汇总所有 agent 的发现，生成完整报告

**不追求速度**：
- 逐节比对，不跳过任何章节
- 逐个函数检查签名
- 逐个类型检查字段
- 发现问题立即记录，不遗漏

## 审计流程

### 1. 准备阶段
- 读取完整的 docs/architecture.md
- 识别所有模块章节
- 提取每个模块的接口定义（类、函数、类型）

### 2. 模块审计（并行）
为每个模块启动一个 sub-agent，执行以下检查：

#### 2.1 文档 → 代码方向
- **类型定义检查**：
  - 文档中提到的 Input/View/Page 类型是否在 src/models/contracts.py 中存在
  - 字段名称、类型注解是否匹配
  - 可选字段（Optional）是否一致

- **服务方法检查**：
  - 文档中描述的服务方法是否在对应的 service 文件中存在
  - 方法签名（参数名、类型、返回值）是否匹配
  - 方法文档字符串是否描述了相同的业务规则

- **异常检查**：
  - 文档中提到的异常类型是否在 src/errors/exceptions.py 中定义
  - 抛出条件是否在代码注释中说明

- **业务规则检查**：
  - 文档中的业务规则是否在代码注释中体现
  - 关键逻辑步骤是否在方法文档字符串中说明

- **基础安全约束检查**：
  - 用户名、密码及其他外部输入的字符、长度、格式和范围是否一致
  - 权限校验位置及可查看数据范围是否一致
  - 密码哈希、敏感字段隐藏和日志脱敏要求是否一致
  - SQL 参数绑定及动态标识符白名单要求是否与实现一致

#### 2.2 代码 → 文档方向
- **公共接口检查**：
  - src/services/ 中所有公共方法是否在文档中说明
  - src/models/contracts.py 中所有导出类型是否在文档中提及

- **遗漏检查**：
  - 代码中有但文档未提及的公共接口
  - 代码中已实现但文档未更新的功能

### 3. 汇总阶段
- 收集所有 sub-agent 的审计结果
- 按严重程度分类问题：
  - **严重**：接口不存在、类型不匹配、参数缺失
  - **中等**：文档描述与代码注释不一致
  - **轻微**：文档过时、措辞不清

- 生成审计报告：
  - 按模块列出所有发现
  - 提供具体的文件位置和行号
  - 建议修复方案

## 实现细节

### Sub-agent 启动示例

```python
# 伪代码
modules = [
    "账号与日志模块",
    "会员与产品模块",
    "课程与预约模块",
    # ...
]

results = []
for module in modules:
    result = await agent(
        f"审计 {module}：比对 docs/architecture.md 中的 {module} 与 src/ 中的实际代码",
        schema={
            "type": "object",
            "properties": {
                "module_name": {"type": "string"},
                "severe_issues": {"type": "array"},
                "moderate_issues": {"type": "array"},
                "minor_issues": {"type": "array"}
            }
        }
    )
    results.append(result)

# 汇总结果
generate_report(results)
```

### 检查清单

每个 sub-agent 使用以下检查清单：

- [ ] 读取文档中的模块章节
- [ ] 提取所有类型定义（Input/View/Enum）
- [ ] 提取所有服务方法签名
- [ ] 在代码中查找对应的类型定义
- [ ] 比对字段名称和类型注解
- [ ] 在代码中查找对应的服务方法
- [ ] 比对方法签名（参数、返回值）
- [ ] 比对业务规则（文档描述 vs 代码注释）
- [ ] 检查代码中是否有文档未提及的公共接口
- [ ] 记录所有不一致之处

## 注意事项

1. **不要跳过 NotImplementedError 方法**
   - 虽然方法未实现，但签名必须与文档一致
   - 检查参数名、类型注解、返回值类型

2. **检查可选参数的默认值**
   - 文档中标注为可选的参数，代码中必须有默认值
   - 默认值类型必须与参数类型一致

3. **检查枚举值**
   - Literal 类型的所有可能值必须在文档中列出
   - 枚举类的所有成员必须在文档中说明

4. **忽略内部实现细节**
   - 只检查公共接口（不以 `_` 开头的方法和类）
   - 私有方法、内部辅助函数不要求在文档中说明
